# Barstronaut website preview brief

Name: Barstronaut
Ticker: $BARSTRO
Status: Preview stage complete; final website assets await design feedback.

## Page and section plan

- /: Shared navigation → Home hero → Origin teaser → Token information → Buying steps → Community hub → FAQ → Shared footer
- /story: Shared navigation → Fictional story introduction → Three-panel rescue comic → Mission log → Community hub → Shared footer
- /buy: Shared navigation → Guide introduction → Token information → Buying steps → Personal transaction checklist → FAQ → Shared footer
- /community: Shared navigation → Community hub → Community activities → FAQ → Shared footer

Four separate page routes serve distinct purposes: Home introduces the joke and project information; Story tells the mascot's fictional rescue; Buy gives practical guidance and pending launch facts; Community collects social destinations and participation ideas.

## Approved visual identity

Preserve the selected warm peach-faced astronaut with large brown eyes, thick expressive eyebrows, violet bubble helmet, off-white padded suit, purple gloves and boots, and bright lime reception bars. Use the approved circular logo and keep the exact name and ticker.
Palette: plum #140B28; panel violet #281346; lime #B6FF35; lavender #B494FF; off-white #F6F1E7.
Use rounded friendly headings and a highly readable sans-serif body. Text, buttons and cards should be built as HTML/CSS rather than baked into final illustrations.

## Preview coverage

22 PNGs: four complete desktop page overviews; twelve detailed distinct sections; two shared component boards; four complete mobile scroll sequences. No unfinished previews.
The mobile boards show Top → Middle → Bottom of one page, read left to right, with all sections in page order.
Detailed section previews govern the proposed composition. Shared component boards 17 and 18 govern navigation/footer reuse across all pages. Overview images communicate order and balance rather than pixel measurements.

## Missing information

Contract address, supply, tax, liquidity status, ownership status, X and Telegram destinations are not supplied. Keep them clearly pending. Never copy placeholder contract text, claim 0% tax, a liquidity lock/burn, renounced ownership or a verified contract without actual supplied evidence. Guide navigation can work before launch; swapping and external destinations remain disabled until configured.
No fake holder counts, community posts, member metrics, transactions, prizes or financial milestones are used.
The Story page and mission log are explicitly fictional; community activities are marked planned.

## Interactions requiring implementation

- Home hero — shown state: Restored signal / replay. Tap a five-bar widget to light the bars in sequence and give the mascot one short bounce. It is a decorative interaction. Provide a static reduced-motion state.
- Story intro — shown state: Layered parallax. Move separate star, moon and mascot layers gently on pointer or scroll. Use static art on mobile and with reduced motion. Raster layers create the illustrated depth; a real 3D model is not required.
- Story comic — shown state: Sequential reveal. Reveal panels in order on scroll. Maintain reading order and show all content immediately when motion is reduced.
- Cards and mission log — shown state: Hover / focus highlight. Slight lift and lime outline on interactive cards. Pending social destination cards stay disabled. Focus must be visible.
- Community activity cards — shown state: Expanded prompt. View prompt expands an inline brief. Caption Control's expanded state is shown in preview 16. Hide prompt collapses it.
- FAQ — shown state: First answer expanded. Accessible accordion, chevron rotation, keyboard operation and natural height transition.
- Shared navigation — shown state: Mobile closed and open. Open from hamburger, close from close control, route selection or Escape; restore keyboard focus. Keep route activity consistent.
- Buy checklist — shown state: Unchecked personal reminders. Visitors can check personal review reminders. Do not label them automatic contract verification. Swapping remains unavailable until real contract and swap configuration exist.
- Contract copy — shown state: Disabled pending state. Do not copy placeholder text. Only enable the control when a validated real address has been supplied, then show a brief copy confirmation.
- Responsive pages — shown state: Three mobile review slices. Mobile boards show Top, Middle, Bottom of one page; they are not alternatives. Implementation uses one continuously scrolling page per route.

## Production corrections and constraints

Generated composition mockups can vary slightly in small props and text spacing. Some signal icons use four bars; final artwork and coded signal widgets must consistently use five bars to match the approved mascot story.
Use exact live HTML text for the final name, ticker and copy. Never crop the name, ticker or controls on mobile. Keep mascot proportions natural; recompose instead of stretching.
Keep illustrations clear of functional text. Use neutral pending icons for liquidity and ownership; a lock graphic must not imply a verified liquidity lock.
Use the shared mobile footer's two-column route grid even where a page overview compresses the links into a row.
On the Buy page suppress the Home-only "Read the buying guide" self-link; retain the step content and pending swap state.
Keep "DESIGN MOCKUP" annotations in the review images, and remove those annotations from a production site after feedback. Actual pending launch facts remain until real values are supplied.
